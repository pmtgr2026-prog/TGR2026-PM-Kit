TGR2026 Trello Kitหน้ารวม Kitเริ่มที่นี่บอร์ดตัวอย่างข้อความการ์ดคู่มือ Trelloคู่มือ Power-Up
คู่มือ Trello

คู่มือ Trello Kit สำหรับผู้เข้าแข่งขัน

Kit นี้ใช้ Trello Free เป็นฐาน ใช้งานได้โดยไม่ติดตั้ง Power-Up เพิ่ม ส่วน Power-Up เป็นตัวช่วยตามความต้องการของทีม

ในหน้านี้สร้างบอร์ดและเพิ่มการ์ดอ่านตัวอย่างและเริ่มงานของทีมเชื่อมงานและบันทึกการเปลี่ยนแปลงสรุปรายงานและเตรียมส่งตรวจความครบและแก้ปัญหาที่พบบ่อย
ย้ำ

ของที่ส่งจริง ส่งด้วย Excel และ MS Word ตาม Template ที่กรรมการจะแจกให้ในวันแข่ง ผ่านช่องทางและเวลาที่กรรมการประกาศ (ในเอกสารนี้เขียนเวลาเป็น xx.xx น. ไว้ก่อน)

ตัวอย่างใน Kit นี้อาจมีเนื้อหามากกว่าสิ่งที่ต้องส่งจริง ตั้งใจให้เห็นภาพรวมของเครื่องมือบริหารจัดการและติดตามงานที่ทันสมัย ทีมเลือกใช้เท่าที่ช่วยให้ทำงานได้จริง การใช้หรือไม่ใช้ Trello ไม่มีผลต่อคะแนน

ข้อมูลโรงเรือนใน Kit เป็นสถานการณ์สมมติสำหรับสาธิตวิธีบันทึก ไม่ใช่โจทย์แข่งขันหรือผลงานจริง ชื่อไฟล์หลักฐานเป็นตัวอย่าง ไม่มีไฟล์ทดสอบหรือ URL หลักฐานจริงแนบมา

ขอบเขต Trello Free

แต่ละทีมใช้หนึ่ง Workspace และหนึ่ง Board ให้ผู้ร่วมงานรวมไม่เกิน 10 คนต่อ Workspace มีได้สูงสุด 10 บอร์ด และไฟล์แนบไม่เกิน 10 MB ต่อไฟล์ ไฟล์ใหญ่ใช้ลิงก์ Drive ได้ [1]

ชุดนี้เป็นไฟล์ช่วยตั้งค่า ไม่ใช่ลิงก์บอร์ดที่สร้างในบัญชีแล้ว CSV หรือ JSON ไม่ใช่ไฟล์นำเข้าบอร์ดอัตโนมัติของ Trello ใช้วิธีคัดลอกข้อความตามหน้าถัดไป

สร้างบอร์ดและเพิ่มการ์ด

ตั้งค่าเพียงครั้งแรก

  • เข้าสู่ Trello แล้วสร้าง Workspace สำหรับทีม
  • สร้าง Board ชื่อ “T00 PM Board” เลือกการมองเห็นตามที่ทีมและกรรมการต้องใช้
  • เชิญเพื่อนร่วมทีมเข้าบอร์ดด้วยบัญชีของแต่ละคน
  • เปิด board_setup/LISTS.txt แล้วสร้าง List ตามชื่อทั้ง 8 รายการ
Listใช้เก็บ
00 เริ่มที่นี่วิธีใช้ ทีม DoD และลิงก์สำคัญ
01 ยังไม่เริ่มงานที่ยังไม่เริ่ม
02 กำลังทำงานที่เริ่มแล้ว
03 ติดขัดงานที่ทำต่อไม่ได้
04 เสร็จรอตรวจงานเสร็จแต่รอตรวจ AC หรือ DoD
05 Doneงานผ่าน AC และ DoD
06 Risk และ Issueความเสี่ยงและปัญหาที่เกิดจริง
07 Checkpoint Decision และ Reportบันทึกการทบทวน ตัดสินใจ และรายงาน

เพิ่มตัวอย่างโดยคัดลอก

เปิด board_setup/titles_by_list เลือกไฟล์ของ List ที่จะเติม คัดลอกชื่อหลายบรรทัดไปวางที่ช่อง Add a card หากมีตัวเลือกสร้างหลายการ์ดให้เลือก หากหน้าจอไม่แยกให้ ให้เพิ่มทีละชื่อได้ [2]

เปิดแต่ละการ์ด แล้วคัดลอกเฉพาะส่วน Description จากไฟล์ example_cards ที่มี ID ตรงกัน ใส่ Members และ Labels เอง สร้าง Checklist ตามชื่อที่ระบุ แล้ววางรายการทีละบรรทัด รายละเอียดจะไม่ตามมาจากการวางชื่อการ์ดเพียงอย่างเดียว

อ่านตัวอย่างและเริ่มงานของทีม

บอร์ดตัวอย่างแสดงสถานะจบรอบแรกของระบบโรงเรือน โดยใช้วันเวลาเหตุการณ์สมมติเดียวกับ Notion Kit งาน Must 6 งานอยู่ Done ส่วน T06 กำลังทำ และ T07 กับ T08 เสร็จรอตรวจ

หนึ่งการ์ดงานควรมีข้อมูลใด

ส่วนตัวอย่างหรือวิธีใช้
ชื่อการ์ดT02 อ่านค่าความชื้นและอุณหภูมิ
Membersเลือก Owner ของงาน; คนอื่นช่วยได้แต่ต้องบอกบทบาท
Labelsงาน Must/Should และรอบ เพื่อแยกจาก Risk หรือ Report
Descriptionแผนเวลา เวลาจริง งานที่ต้องรอ AC ผลตรวจ และข้อจำกัด
Checklistแยก AC ของงาน DoD ของทีม และงานที่ต้องรอก่อน
Commentsเวลา พบอะไร ทำอะไร เพราะอะไร ผลเป็นอย่างไร

เริ่มบอร์ดของทีมจริง

สร้างบอร์ดใหม่ตามโครงสร้างเดิม ใช้ practice_templates/TASK.txt เป็นการ์ดต้นแบบแล้ว Copy สำหรับแต่ละงาน เปลี่ยนรหัสทีม งาน Owner และ AC เริ่มงานใน List ยังไม่เริ่ม อย่าคัดลอกผล Done ของตัวอย่างมาเป็นสถานะจริง

Checklist ที่แนบเป็นเงื่อนไขให้ตรวจ ไม่ได้ถูกทำเครื่องหมายผ่านให้ ทีมต้องตรวจและบันทึกหลักฐานจริง การทำครบรายการหรือเขียนโค้ดเสร็จไม่ได้ยืนยันว่า AC และ DoD ผ่านโดยอัตโนมัติ

เชื่อมงานและบันทึกการเปลี่ยนแปลง

ทำ Relation แบบฟรีด้วยลิงก์การ์ด

  • เปิด T02 แล้วคัดลอกลิงก์การ์ด
  • เปิด T03 สร้าง Checklist “งานที่ต้องรอก่อน” แล้วเพิ่มลิงก์ T02
  • แนบลิงก์ T03 ย้อนกลับใน T02 พร้อมคำอธิบาย “งานที่รอผลจากการ์ดนี้”
  • ทำเช่นเดียวกันกับรายการใน board_setup/RELATION_MAP.md

สำหรับ Risk Issue หรือ Decision ใช้ข้อความว่า “เกี่ยวข้องกับ” แล้วแนบลิงก์ทั้งสองฝั่ง เช่น R01 เกิดเป็น I01 และเลือก D01 เพื่อแก้ หลีกเลี่ยงการตีความความเกี่ยวข้องทุกชนิดเป็นงานที่ต้องรอก่อน

การเชื่อมแบบนี้ใช้ Checklist และ Attachments ไม่ใช่ฐานข้อมูล Relation และไม่เลื่อนวันเวลาหรือปลดบล็อกให้อัตโนมัติ ทีมต้องตรวจสถานะเอง วิธีนี้สอดคล้องกับแนวทาง dependency ของ Trello [3]

ตัวอย่างการ Monitor

I01 เกิด 14.00 น. ค่าดินแกว่ง กระทบ T02/T03 ทีมเลือก D01 ตรวจสายและเฉลี่ยค่า 14.40 น. ผ่านเกณฑ์จึงปิด I01 เวลา 15.00 น. C01 นำไปสู่ D02 คงเริ่ม T09 ที่ 16.00 น. เพราะ T03 เสร็จก่อน

C02 เวลา 16.00 น. พบ T06 ยังไม่พร้อม ทีมเลือก D03 เลื่อนงาน Should และจำกัด T09 ให้ทดสอบเซ็นเซอร์จริงกับ JSON ที่เตรียมไว้ รายงานต้องระบุว่ายังไม่ยืนยัน inference สดจาก Pi ถึง Dashboard

สรุปรายงานและเตรียมส่ง

จบรอบให้สรุปข้อมูลที่ตรวจสอบได้

  • เทียบแผนกับผลจริง อ้าง Task ID และผล AC/DoD
  • สรุปปัญหา วิธีแก้ และผลหลังแก้ อ้าง Issue/Decision
  • ระบุเหตุการณ์การทำงานร่วมกันและการช่วยตรวจงาน
  • บันทึก Retro Keep Problem Try พร้อม Owner และจังหวะติดตามผล
  • ใส่หลักฐานที่เปิดได้ พร้อมตำแหน่งที่ยืนยันแต่ละข้อ

เก็บแผน Risk รายงาน และหลักฐานในชุดชื่อเช่น T01-R1-v1 แล้วบันทึกลิงก์ในรายงาน ให้กรรมการหรือกรรมการเก็บสำเนาที่ทีมแก้ทับไม่ได้ ถ้าแก้ภายหลังแยก v2 ตามขั้นตอนกรรมการ

สำรองบอร์ดได้ผ่านเมนู Board แล้วเลือก Print Export and Share แล้วเลือก JSON ใน Free ส่วนการส่งออก CSV แบบบอร์ดเป็นฟังก์ชัน Premium JSON เป็นข้อมูลสำรอง ไม่ใช่รายงานพร้อมส่ง และไม่รวมไฟล์หลักฐานภายนอกครบให้เอง [4]

ตรวจความครบและแก้ปัญหาที่พบบ่อย

อาการหรือคำถามสิ่งที่ตรวจ
วางชื่อแล้วรายละเอียดไม่ตามมาวางชื่อสร้างเฉพาะการ์ด ต้องใส่ Description Members Labels และ Checklist เพิ่ม
งานรอตรวจแต่แสดง 100%คงไว้เสร็จรอตรวจจนกว่าจะผ่าน AC และ DoD
การ์ด Risk ปะปนกับงานใช้ List แยกและ Label งาน สำหรับกรองหรือนับ
เปิดลิงก์หลักฐานไม่ได้ตรวจสิทธิ์ Drive หรือ repository แยกจากสิทธิ์ Trello
มี Power-Up แต่บางคนใช้ไม่ได้ตรวจการเชื่อมบัญชี สิทธิ์ และข้อจำกัดของ Power-Up นั้น
ไม่มีเวลาเรียนรู้เครื่องมือใช้ Excel และ MS Word ต่อได้ รักษา ID และหลักฐานให้ครบ
